# Manual-control research and task timer

Weekly Plan tasks and Focus share one backend-persisted session and global mini timer. Start a task stopwatch or choose a task/standalone countdown on Focus. Start/Resume continues until an explicit Pause or Stop, including while working in Zotero, an editor, another website, or with PhD Quest completely closed. Reopening fetches the same session and its current elapsed time. Previously paused sessions stay paused.

## Timing and synchronization

For running sessions, measured milliseconds equal accumulated `confirmedMilliseconds` plus `max(0, serverNow - intervalStartedAt)`. Paused and stopped sessions use their accumulated/final duration. The existing accumulated field keeps its name for compatibility; it no longer represents an activity cutoff. Pause checkpoints the interval; Resume starts a new interval without duplicating old time. Only explicit Stop finalizes history. Countdown targets indicate a target reached, while elapsed time continues beyond the target until a user command. Managed duration is not truncated at the old seven-day cap. Legacy immutable save validation retains its original limits.

Heartbeat leases, interaction windows and close-triggered pauses no longer control duration or lifecycle. Existing lease/activity metadata is ignored for live timing; no destructive migration runs. The optional heartbeat API remains a token/sequence-protected checkpoint for older clients and never expires or finalizes a session. `reconcile` cannot pause a session. Server timestamps alone decide persisted duration; browser clocks and interval callbacks never award time.

The frontend uses BroadcastChannel notifications after explicit commands and a lightweight current-session GET every 15 seconds. Returning to a visible tab, focusing the window, restoring a page or reconnecting requests a fresh authoritative anchor. Display interpolation uses monotonic and wall elapsed time so computer sleep is included even when a browser suspends its monotonic clock. Display estimates resynchronize with the server; pause/stop durations always come from the server. Closing a tab, hiding it, losing focus, inactivity, network loss and component destruction send no pause/stop commands. A network failure retains the running session and explains that time continues.

## Consistency and time application

The existing partial unique active-slot index enforces one running/paused session per workspace. Application-wide transactions and quoted `If-Match` protect lifecycle changes, replacement/restore and task-time application. Cross-tab commands require the captured session identity/version; a queued stale command cannot target another session. Old owner tokens and replayed/out-of-order synchronization requests are rejected. No browser leader, presence lease or Web Locks support is required for timer correctness.

Stop saves measured history. Review the original duration and an optional effective duration of 0–1440 whole minutes. The default is `floor(measuredSeconds / 60)` per session; fractional milliseconds are preserved during running/pausing and seconds are floored once at finalization. Save without applying can preserve a correction and leaves task time unchanged. Confirmed application atomically adds effective minutes to the linked task's existing actual minutes exactly once, with before/after provenance and a 1440-minute resulting task limit. Manual edits never reset application status. Missing tasks preserve history and block application to another task.

Historical applications remain separate Focus totals and are never added retroactively to task actual time. Original measured seconds remain immutable after stopping; summaries use measured seconds by end date in APP_TIMEZONE and Sunday–Saturday weeks. Breaks share the timer, require explicit pause/stop, and remain excluded from research history, summaries and task application. No timer operation automatically completes tasks, goals or checkpoints or awards XP/streak/proficiency changes.

## API and backup compatibility

The existing `/api/focus-sessions` routes remain: GET current/history/summary/task-times/application-preview; POST start, `:id/pause`, resume, stop, claim, reconcile, heartbeat, correction and apply-time. Lifecycle/correction/new task-time application require If-Match. Browser Pause requests include the existing tab `ownerId`; empty browser close-pause payloads from cached older clients are rejected without mutation. Originless CLI Pause remains supported. The idempotent legacy save and uncorrected legacy `{confirm:true}` application remain compatible. JSON-only, exact-origin mutations remain enforced.

Version-1 backups keep their schema version and optional Focus section. The optional `timerPolicy: "manual"` identifies new/updated manual records. Their running/paused state and timing anchor survive export/restore; restore invalidates owner credentials and rotates editor tokens. An explicitly restored old heartbeat-era active backup keeps its established conservative paused-restore behavior. Existing auto-paused records are never silently resumed. Old saved sessions, corrections, application markers and manual task totals round-trip without replaying applications. Digest/revision validation and atomic rollback remain intact.

Refresh all existing tabs after upgrading both applications so cached clients no longer send the obsolete close-pause or activity-heartbeat requests. Older local recovery snapshots remain available for explicit save/discard; they never create a second running timer.

## Verification

Use Node 24 and [the verification guide](VERIFICATION.md). `npm run test:focus` covers explicit lifecycle, three hours without heartbeats, ignored legacy leases, preserved paused records, concurrent commands, correction/application, v1 backup compatibility and rollback on owned UUID databases. Safe unit tests cover elapsed-time calculations beyond inactivity/lease/target limits. Frontend tests cover close/blur/visibility without mutations, offline display, sleep interpolation, synchronization and stale commands. The consolidated browser workflow tests closing all app tabs for simulated hours, reopening the same timer, network loss, simulated sleep/wake, layouts, keyboard controls and explicit exactly-once application. Actual screen-reader or physical power-loss testing is not claimed.
