# Research roadmap import

On the Roadmap page, choose **Import roadmap**, select a JSON file, review all twelve chapters and the existing progress counts, then type `REPLACE ROADMAP` and confirm. No import occurs during preview. Keep a full workspace backup first if the old roadmap progress is needed later.

The version-1 file contains `schemaVersion: 1`, a lowercase hyphen-separated `roadmapId` (max 100), nonblank `title` (max 160), `durationYears: 3`, and exactly twelve ordered `levels`, numbered 1 through 12. Every level requires a title (160), description (3000), 1-20 objectives (300 characters each), and 1-100 checkpoints. Checkpoints require a unique lowercase hyphen-separated `id` within their level (100), title (300), boolean `required`, and optional description (3000). Every level needs a required checkpoint. Text is trimmed. Limit: 500 KiB. Unknown fields, saved progress, database IDs, timestamps, XP and settings are rejected. The [complete generic example](contracts/roadmap.v1.example.json) is sample content only and is never seeded/imported automatically.

- `POST /api/roadmap/import/preview`: `{roadmap}`. Returns normalized content, chapter/objective/checkpoint totals, replacement/reset warnings, current completion/history counts, a SHA-256 digest and destination revision. Snapshot reads only.
- `POST /api/roadmap/import/confirm`: `{roadmap, digest, revision, confirmation: "REPLACE ROADMAP"}`. Revalidates content and digest. Uses the same application-wide transaction guard as roadmap edits, progression and workspace restore. Changed revisions and duplicate submissions return 409; preview and explicitly confirm again. All twelve records are replaced in one transaction. Failure rolls back the complete replacement.

Level 1 becomes current; levels 2-12 are locked. Checkpoint completion, evidence and validation history are reset. The imported checkpoint `required` flag maps to the existing `mandatory` field. Weekly plans, task state, XP, daily activity, goals, settings and achievements are untouched; goals linked to fixed level numbers remain linked to those numbers in the new map. Importing grants no XP or achievements. Historical roadmap achievements remain unlocked and do not imply progress in the replacement map.

Version-1 full-workspace backup structure is unchanged. Imported content and subsequent progress are exported/restored normally, and old backups remain accepted. Historical roadmap achievement unlocks may predate all records in a replacement map; that timestamp history is accepted without requiring erased checkpoints in the active map. Other achievement evidence checks remain unchanged. The file's journey title and ID are preview metadata only; they are not persisted or added to backups in this sprint. Level content is persisted and preserved on restart. The dashboard loads fresh data when opened after import.

Focused verification: build, then run `node test/research/roadmap-import.check.cjs` with MONGODB_URI set. This check creates/removes only its own random validation databases; never replace the real workspace roadmap for testing.
